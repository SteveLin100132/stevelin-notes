# 專案管理系列：學習地圖

這系列筆記是把以前學到的專案管理皮毛整理下來。我不是 PM 背景出身，內容多半來自老東家的實務經驗；
為了確認概念沒有偏掉，也會和顧問 Danny 核對想法，把他建議的部分一併收進來。

每一章盡量由淺入深、循序漸進，並搭配互動的視覺化元件幫助理解。

:::tip{title="開始前"}
專案管理先要釐清「**在管什麼**」，才談得上「怎麼做、誰來做、用什麼做」。下面的閱讀順序就是照這個邏輯排的。
:::

## 為什麼是這個順序？

每一章都建立在前一章的結論之上：

1. **先分清「專案 vs 產品」**：它決定了之後該用哪一套管理模式，是後面所有選擇的地基。
2. **再看「方法論」**：知道要管理什麼之後，才依內容選擇合適的方法，看是用 :tip[瀑布式（Waterfall）]{content="以階段推進的線性開發方式：需求、設計、開發、測試、上線依序進行，前一階段完成才進入下一階段。"} 還是 :tip[敏捷式（Agile）]{content="以短週期迭代為核心的開發方式：小步交付、持續回饋、擁抱需求變動。"} 來執行。
3. **接著釐清 :tip[R&R]{content="Role & Responsibility，角色與職責：界定每件事誰拍板、誰執行、誰被諮詢、誰只是被通知。"}**：同一群人在不同方法論底下，權責流向完全不同。把每個角色的責任界定清楚，在專案管理中相當重要，也是日後釐清爭議的依據。
4. **深入 :tip[Waterfall SDLC]{content="Software Development Life Cycle，軟體開發生命週期：把專案從構思到退役拆解成數個明確階段。"}**：瀑布式是很經典的專案管理手法，該章會說明「階段、會議、交付物」如何環環相扣。
5. **最後是「工具」**：前面都是觀念，工具是把這些觀念落地執行的載體。
