# 報告式版面（一頁一份報告）

作者要的「專業」簡報，是顧問報告、月會匯報那種**高資訊密度但結構清楚**的頁面：
每頁像一份 one-pager，看得出重點、看得出結構、每一區都有最適合的呈現形式。
參考來源：作者的「2026 年 9 月工程師團隊月會簡報」P7（MVP 範圍定案）、P9–P11（R&R、規格產出流程、Scrum 前提）。

範例實作：`.notecraft/components/pm-01-project-vs-product.deck.tsx`（版面零件在 `── 版面零件 ──` 段落，直接複製）。

## 頁面骨架

```
┌ 編號徽章 · EYEBROW ─────────────────── [右上 pill：這頁的一句結論] ┐
│ 標題（講主題或結論）                                                  │
│ ── 橘線                                                               │
│ （選用）頂端橫帶：流程帶 / 兩張定義卡                                 │
│ 一 小節標題 │ 二 小節標題        │ 三 小節標題（窄欄 340–380px）      │
│ 內容        │ 內容               │ 內容                              │
│             │                    │ 結論條                            │
│ （選用）頁底說明帶：小插圖 + 「為什麼」一段話 / 下一步              │
└───────────────────────────────────────────────────────────────────────┘
```

- **右上 pill = 這頁的一句結論**：用 chrome 的 `pill` 欄位（`tone: "blue"` 一般、`"orange"` 警示或反直覺）。標題講主題，pill 講結論，兩者不要重複。
- **2–3 個編號小節**：`SecHead`（「一　」+ 圓角方形 icon 章 + 藍色粗體）。第三欄常是窄欄，放結論、判讀、決策卡。
- **欄與欄用細線分隔**（`divider(c)`：左 1px 線 + 28px 內距），**不要**把每一區都包成卡片。卡片只給真的是「一個單位」的東西（決策卡、定義卡）。
- **頁底**：「為什麼」說明帶（`WhyBand`：小圖 + 標題 + 一段理由），或結論條，或下一章引導。

## 每一節挑一種呈現形式

| 內容 | 形式 | 零件 |
| --- | --- | --- |
| 依序的步驟、生命週期 | 橫向流程帶，最後一步用色框強調 | `Flow` |
| 同一組屬性的 N 個項目 | 細線清單：icon + 粗體名詞（固定寬）+ 說明 | `ListRow` |
| 問題 × 兩種答案 | 三欄對照表：問題 / 偏向 A / 偏向 B，答案前加色點 | grid + `SideTag` |
| 需要做決定、有建議答案 | 決策卡：64px 概念小圖 + 問題（小灰字）+ 大字答案 + 補充；重點卡用橘框 | `FocusCard` |
| 兩個概念的定義對照 | 定義卡：小圖 + 標籤 + 大字定義 + 說明，上緣色條 | `DefCard` |
| 時間長短、流程耗時 | 共用軸的泳道甘特，每列標負責角色 | `Lane` |
| 2×2 結果 | 象限，每格同構小場景，危險格橘框 + 警示 icon | `QuadScene` |
| 編號重點 | `01 / 02 / 03` 大號 mono 數字 + 粗體標題 + 說明 | — |
| 收斂 | 結論條（左 5px 藍線、淡藍底、粗體） | `Concl` |
| 但書、暫定、出處 | 橘色附註膠囊 | `Note` |

## 密度與字級（1600×900）

- 小節標題 `DS.body`（20）900；清單名詞 `DS.body` 700；說明文字 `DS.small`（17）；標籤、附註、軸刻度 `DS.micro`（14）。
- 決策卡的答案 `DS.h4`（24）900；編號數字 `DS.h4` mono。
- 一頁約 200–350 字，但每個字都在結構裡（清單、表格、卡片），不是段落。只有「為什麼」說明帶允許一段 60–80 字的文字。
- 流程帶、清單列、表格列之間用 1px 細線（`c.border`），不用陰影。

## 插圖在報告式版面中的位置

- **插圖面板**：小節裡一塊 `Panel`（淡底 + 細框），放一張情境插圖，下方用兩欄小字說明（例：分岔路口場景下方「專案：一次性交付｜產品：持續經營」）。
- **64px 概念小圖**：放在決策卡、定義卡、說明帶左側（`MiniDeliver`、`MiniValue`、`MiniRisk`、`MiniBacklog`、`MiniWhy`）。一張小圖只講一個概念。
- **象限／流程的小場景**：同構物件只換關鍵元素。
- 插圖不再是頁面的主角；主角是結構，插圖負責讓每一區「一眼看懂在講什麼」。

## 檢查清單

- [ ] 每個內容頁都有右上 pill，且 pill 是結論不是主題
- [ ] 內容區分成 2–3 個編號小節，欄間只用細線
- [ ] 每一節的呈現形式跟內容形狀對應（上表）
- [ ] 至少一個結論條或說明帶，讓讀者知道這頁的收斂點
- [ ] 但書、示意值、暫定內容用橘色附註或 footnote 標出
- [ ] 卡片內容加總高度要算：`flex: 1` 的卡片在欄高不足時會被裁掉（JS 檢查 `scrollHeight > clientHeight`）
